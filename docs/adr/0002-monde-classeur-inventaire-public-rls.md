# Monde classeur : inventaire des profils publics via RLS

Le monde classeur affiche jusqu’à 80 espèces du classeur (une mesh par espèce, anneaux par rareté, carte vitrine garantie si possédée). Les visiteurs y accèdent quand le **profil joueur** est public, y compris sans connexion ; le titulaire y accède toujours. Pour charger l’inventaire d’un autre joueur, on ajoute une **policy RLS** sur `user_cards` : lecture autorisée pour `anon` et `authenticated` lorsque la ligne `profiles` du `user_id` ciblé a `is_public = true`, en plus des policies « own row » existantes. Le plafond, le tri rareté + vitrine, et le libellé « X sur Y espèces » restent calculés côté applicatif (Next.js) ; la RLS ne fait qu’ouvrir la lecture des lignes inventaire, alignée sur la même règle que la visibilité du classeur dans le glossaire.

**Considered options** : lecture inventaire autrui uniquement via client service role / SQL serveur sans policy élargie (rejeté — alignement explicite DB ↔ règle « profil public » et requêtes possibles avec la clé anon) ; vue ou snapshot public dénormalisé (rejeté — latence et duplication pour un MVP) ; toggle « classeur » séparé du profil (hors scope — une seule visibilité).

**Consequences** : migration Supabase avec policy `user_cards` jointe à `profiles` ; revue sécurité (pas de fuite pour profils privés, pas d’écriture élargie) ; tests RLS profil public / privé / visiteur anonyme ; pas de vue 2D publique du classeur dans ce livrable ; décor CC0 hébergé dans le dépôt ou le stockage projet ; fallback WebGL vers `/collection` pour le titulaire, message sur le profil pour les autres.
